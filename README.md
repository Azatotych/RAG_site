# Локальный ассистент (SPA)

React + TypeScript + Vite чат-UI для локального LLM-бэкенда. Сообщения и выбранные документы живут только в памяти вкладки (не сохраняются между перезагрузками). Поддерживаются светлая/тёмная темы с переключателем и запоминанием выбора в `localStorage` (по умолчанию берётся системная тема).

## Возможности v3
- Переключение режимов GPT/RAG в верхней панели. Переключение сбрасывает чат, выбранные документы и закрывает открытые меню/панели.
- RAG режим: выбор литературы через боковой Drawer, дерево разделов из мок-данных, добавление/удаление документов в контексте (лимит 10) и выпадающее меню «Выбранные документы ▾».
- Прогресс-бар «Контекст: N/10» с цветовой индикацией заполнения и красным toast при попытке превысить лимит.
- Обработка ошибок API: после каждого отправленного сообщения сначала добавляется сообщение пользователя, затем — ответ ассистента или красное error-сообщение с причиной и URL.
- Темизация через CSS variables, фон с фирменной подложкой, адаптивная верстка.

## Переменные окружения
`.env` или переменные среды:
```
VITE_API_BASE_URL=http://localhost:8080
VITE_CHAT_ENDPOINT=/api/chat
```

### GPT API (детально)
Маршрут для режима GPT: `POST ${VITE_API_BASE_URL}${VITE_CHAT_ENDPOINT}`. Набор полей полностью соответствует тому, что отправляет UI; ниже — договорённости по формату.

**Тело запроса**
```json
{
  "mode": "gpt",
  "messages": [
    {"role": "user", "content": "текст пользователя"}
  ],
  "stream": false
}
```

- `mode` — фиксировано `"gpt"` (UI всегда отправляет это значение в GPT-режиме).
- `messages` — массив истории текущей вкладки (память не сохраняется при перезагрузке). UI всегда кладёт последнюю реплику пользователя; предыдущие сообщения будут переданы, если пользователь не очистил чат.
- `stream` — флаг для будущей потоковой генерации; сейчас UI ожидает обычный JSON-ответ и не требует SSE.

**Ожидаемый ответ**
```json
{ "reply": "текст ответа ассистента" }
```

- Поле `reply` обязательно. Если оно отсутствует или ответ не JSON, UI покажет красное error-сообщение и продолжит работу.

**Пример cURL**
```bash
curl -X POST "${VITE_API_BASE_URL}${VITE_CHAT_ENDPOINT}" \
  -H "Content-Type: application/json" \
  -d '{"mode":"gpt","messages":[{"role":"user","content":"Привет!"}],"stream":false}'
```

**Ошибки, которые UI считает недоступностью модели**
- Переменные окружения не заданы или пустые.
- Сетевая ошибка (DNS, отказ в соединении, таймаут, `TypeError: Failed to fetch`).
- HTTP-статус не 2xx.
- Ответ не JSON или нет поля `reply`.

В этих случаях сообщение пользователя остаётся в ленте, а следом добавляется красное сообщение формата:
```
Ошибка: модель недоступна
Причина: <краткое пояснение>
URL: <полный адрес запроса>
```

### Поведение при недоступном API
Если переменные окружения пусты или API не отвечает (ошибка сети/DNS/таймаут, HTTP не 2xx, не-JSON или нет `reply`), приложение продолжит работу: текст пользователя остаётся в ленте, следом выводится красное сообщение об ошибке с причиной и URL.
